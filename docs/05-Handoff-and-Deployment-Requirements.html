2. How to Run (Development)

# prerequisites: Node.js 18+, pnpm 8+, PostgreSQL 14+
pnpm install

# backend (port 3001, API prefix /api, Swagger at /api/docs)
DATABASE_URL=postgres://user:pass@host:5432/db \
JWT_SECRET=change-me \
pnpm --filter @workspace/nestjs-server run dev

# frontend (port 3000; proxies /backend/api/* to the backend)
BACKEND_URL=http://localhost:3001 \
pnpm --filter @workspace/nextjs-app run dev

Development seed operations require administrative authentication. Do not publish or reuse development credentials. Production provisioning must be controlled, auditable, and separate from normal application startup.

4. Deployment Requirements

RequirementDetail
Node runtimeNode.js 18 or newer, pnpm available at build time.
DatabasePostgreSQL 14+ (managed service recommended: Neon, Supabase, RDS, Cloud SQL). ~100 MB is plenty to start.
ProcessesTwo services: frontend (Next.js server or Vercel) and backend (NestJS, long-running Node process).
NetworkingFrontend must reach the backend over HTTPS; browser only ever talks to the frontend origin (same-origin proxy).
TLSTerminate HTTPS at the platform/load balancer.
Memory512 MB per service is sufficient for small deployments.

5. Production Checklist

✔Item
☐Require a strong JWT_SECRET and remove the hard-coded fallback.
☐Stop startup password resets/account reactivation; keep seed and account provisioning controlled and production-gated.
☐Turn off TypeORM synchronize and adopt migrations (typeorm migration:generate) — auto-sync on a live database can drop/alter columns unexpectedly.
☐Enable database backups (daily snapshot is enough initially).
☐Restrict CORS on the backend to the frontend's production origin.
☐Restrict or disable Swagger and seed operations in production.
☐Resolve high security-scan findings or record a reviewed risk acceptance.
☐Run automated role, branch, order, payment, inventory, report, notification, and export checks.
☐Set up log retention / error alerting on both services.
☐Create real staff accounts with strong passwords; deactivate demo users.
Data safety: the system currently relies on synchronize:true. Before the first production deploy, generate the schema once, then disable synchronize. Never point a synchronized dev backend at the production database.

6. Operational Notes for the Next Team

  • Verification habit: run npx tsc --noEmit inside artifacts/nextjs-app after frontend changes. Avoid running next build while the dev server is running.
  • Polling: all live pages poll every 10 s; there is no WebSocket layer to maintain.
  • Exports: Excel/PDF exports happen in the browser (xlsx, jspdf) — no server-side rendering service is needed.
  • Role logic: sidebar visibility lives in src/components/sidebar.tsx; per-page role behavior is in each page component; backend guards are authoritative.
  • Profitability math: food cost is estimated from stock deduction/waste movements × unit cost; accuracy depends on the store team recording usage.
  • API reference: Swagger UI is served by the backend at /api/docs.
